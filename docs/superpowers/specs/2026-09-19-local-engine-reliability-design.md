# 85 数字多媒体下载助手：本地引擎稳定性与统一 WebUI 设计

日期：2026-09-19  
状态：待用户审阅  
适用版本：v1.3.0 及后续版本

## 1. 目标与边界

本次工作不重新建立产品，而是在现有 `85-media-assistant` 工程上完善“统一网页 + 本地引擎”的使用方式。

产品最终体验为：用户从同一个公开网址进入下载助手；第一次使用时只安装一次与当前系统匹配的本地引擎；以后仍然打开同一个网页，网页自动连接这台电脑上的本地引擎。识别、预览、下载、转封装和保存都由用户自己的电脑完成，不依赖付费云服务器，也不把媒体、平台会话或下载记录上传到项目服务器。

本次不包含超分功能，不尝试绕过付费内容、DRM、登录验证、地区限制或平台访问控制。

正式支持范围只有：

- Windows 10/11 x64。
- macOS Apple Silicon（M 系列芯片）。

后续发布不再构建 macOS Intel 安装包，不再在下载页显示 Intel 入口，也不再把 Intel 包写入新版本清单。已经发布的旧 Intel 文件保留归档，不在本次工作中删除。

## 2. 总体架构

系统由三个部分组成：

1. **统一入口页**：托管在 GitHub Pages，负责系统识别、安装引导、连接状态展示和打开本地工具。
2. **轻量本地守护程序**：随用户登录静默启动，只监听本机回环地址，负责健康检查、启动本地服务、故障恢复和更新协调。
3. **本地 WebUI 与任务引擎**：在 `127.0.0.1:8515` 提供完整操作界面和 API；识别或下载时才按需启动 yt-dlp、FFmpeg、FFprobe、Deno 或隔离浏览器进程。

统一入口页不是媒体处理服务器。浏览器的安全限制决定了普通 HTTPS 网页不能在未经用户确认的情况下静默安装程序、启动任意本地可执行文件，或可靠绕过浏览器的外部协议确认。因此第一次安装仍须由用户确认；安装完成后，由安装程序启动本地引擎并打开本地 WebUI。以后统一入口页可通过本地健康检查和自定义协议协助打开或修复，但不得向用户承诺“网页无确认自动安装”。

## 3. 正常使用流程

### 3.1 首次使用

1. 用户打开统一网址。
2. 页面识别 Windows x64 或 macOS Apple Silicon，并显示唯一的推荐安装按钮。
3. 用户下载安装包并完成一次系统确认。
4. 安装程序注册本地守护程序、开机登录启动项和 `mediaassistant85://` 自定义协议；不创建桌面图标。
5. 安装完成后立即启动本地守护程序，等待健康检查通过，再由默认浏览器打开 `http://127.0.0.1:8515/`。
6. 用户进入与现有工具一致的 WebUI，并可立即使用。

### 3.2 后续使用

1. 用户登录系统后，本地守护程序静默启动。
2. 用户打开统一网址。
3. 页面探测本机引擎；连接成功后显示“打开网页版工具”。
4. 用户点击后进入本机 `127.0.0.1:8515` 的工具页面。

如果浏览器阻止统一入口页直接探测本地 HTTP 服务，页面改用自定义协议唤醒本地守护程序；守护程序自行打开本地 WebUI。网页必须明确展示当前状态，不能让按钮在无反馈的情况下失效。

## 4. 统一入口页状态模型

入口页只展示一个主要动作，并根据检测结果进入以下状态：

1. **未安装**：展示与系统匹配的安装按钮和“一台电脑只需安装一次”。
2. **正在连接**：展示短时探测进度，不重复弹窗，不自动循环拉起外部协议。
3. **已连接**：主要按钮为“打开网页版工具”。
4. **正在恢复**：本地程序存在但服务尚未就绪，显示自动恢复进度，并允许用户重新检测。
5. **需要修复**：连续恢复失败或版本不完整，主要按钮为“修复本地引擎”，辅助入口为“查看诊断”。

每次点击必须在页面上立即产生状态反馈。禁止出现点击“打开”后无变化的情况。

## 5. 节能常驻策略

本地常驻只保留轻量守护程序，不常驻 GPU 任务，不提前加载 FFmpeg、yt-dlp、Deno、Chromium 或下载队列工作进程。

- 空闲时不使用 GPU。
- 空闲 CPU 应接近 0，仅由低频健康检查产生瞬时活动。
- 守护程序只保留必要内存；发布验收记录 Windows 和 macOS 的实际空闲内存，不能以未经测量的固定数值对外宣传。
- 识别、预览、下载和转封装开始时按需启动重型组件。
- 单项任务结束后释放子进程；所有任务完成且超过短暂复用窗口后，重型组件全部退出。
- 用户关闭浏览器不终止正在进行的下载；守护程序继续维护任务状态。

守护程序默认每约 15 秒执行一次轻量内部状态检查；没有任务时不访问平台、不扫描磁盘、不启动浏览器。

## 6. 故障恢复与熔断

守护程序负责确保同一时间只有一个本地服务实例，并验证 8515 端口上的服务确实属于本产品。

当本地服务异常退出时，采用 2 秒、5 秒、15 秒、60 秒的退避间隔恢复。60 秒为同一故障周期的最大间隔。若短时间内多次启动后仍无法通过健康检查，进入熔断状态，停止无限拉起进程，并向统一入口页或本地诊断页报告明确原因。

恢复优先级：

1. 检查端口占用、程序完整性和当前活动任务。
2. 尝试重启本地服务。
3. 检查当前版本文件与组件清单。
4. 必要时回退到最后一个已验证版本。
5. 仍失败则进入“需要修复”，保留日志和用户数据。

浏览器端断线时不清空已识别作品、输入链接或下载选择；页面显示“本地引擎正在恢复”，采用有限退避重新连接。恢复成功后从本地状态重新同步，而不是创建重复任务。

## 7. 本地数据与任务持久化

作品队列、识别结果摘要、下载任务、下载进度、用户设置、更新状态和必要的恢复元数据存放在用户数据目录中。采用 SQLite 作为结构化状态存储，并保留已有媒体文件与临时分片的文件系统布局。

- 写入采用事务，避免程序异常退出后留下半条记录。
- 下载任务使用稳定任务 ID；浏览器重连不能重复提交同一任务。
- 未完成下载保留可验证的临时文件，支持重新开始或在工具链允许时断点续传。
- 下载完成后先验证输出，再把任务标记为成功并播放完成提示音。
- 卸载默认不删除已下载媒体；清除本地数据必须由用户主动确认。
- 平台临时会话失效只影响对应识别任务，不应让整个本地服务退出。

## 8. 本地安全与隐私

- HTTP 服务只绑定 `127.0.0.1`，不得监听局域网或公网地址。
- API 使用仅保存在当前设备上的随机密钥签发短期本地会话令牌。
- 健康检查可返回最小非敏感信息；识别、下载、设置与日志接口必须校验本地会话。
- 不读取用户日常浏览器配置、历史或 Cookie；需要平台验证时继续使用工具自己的隔离会话。
- 入口页只负责连接状态和版本引导，不接收媒体、Cookie、下载记录或本地日志。
- 日志默认去除会话令牌、Cookie、完整签名媒体地址等敏感字段。

## 9. 更新与回退

更新包和版本清单必须进行签名验证；签名无效、文件哈希不匹配或版本不兼容时拒绝安装。

- 有活动下载时不强制重启本地服务。
- 更新先写入独立版本目录，验证完整后再切换当前版本指针。
- 切换后必须通过启动和健康检查；失败则自动切回上一个已验证版本。
- 离线或更新服务不可用时继续使用当前版本。
- 前端静态文件与本地 API 具有兼容版本；不兼容时显示更新提示，不能静默进入错误页面。

## 10. Windows 安装行为

- 发布单一 Windows 10/11 x64 安装程序。
- 安装本地引擎、WebUI、守护程序以及所需的 yt-dlp、FFmpeg、FFprobe、Deno 等组件。
- 使用当前用户级启动项，不要求程序以管理员身份长期运行。
- 注册 `mediaassistant85://` 自定义协议。
- 不创建桌面图标，不弹出终端窗口。
- 安装完成后启动守护程序；健康检查通过后打开本地 WebUI。
- 升级保留设置、记录、平台隔离会话和下载文件。

## 11. macOS Apple Silicon 安装行为

- 只发布 Apple Silicon DMG，不再发布 Intel 版本。
- 应用安装到标准 Applications 目录后，注册当前用户 LaunchAgent。
- LaunchAgent 登录后静默运行，不打开终端，不显示常驻主窗口。
- 注册 `mediaassistant85://` 自定义协议。
- 首次启动受 macOS Gatekeeper 约束时，入口页提供简明的“隐私与安全性”确认说明。
- 安装完成或首次确认后，启动守护程序；健康检查通过后打开本地 WebUI。

## 12. 日志、诊断与修复

日志按大小或日期滚动，限制总占用，并区分守护程序、API、识别、下载和更新模块。普通页面只给用户可理解的结论，技术详情放在可展开区域。

“一键修复”依次执行：

1. 检查本地守护程序和启动项。
2. 检查 8515 端口冲突。
3. 检查当前版本、内置组件和签名清单。
4. 重建安全的临时目录和损坏的非用户配置。
5. 尝试恢复服务或回退版本。

修复不得删除下载文件、作品记录、用户设置或有效的平台隔离会话。需要清空某项数据时必须单独说明并由用户确认。

## 13. 发布与验收标准

每次正式发布至少验证：

- Windows 10/11 x64 全新安装、覆盖升级、登录自启动、无终端弹窗、无桌面图标。
- macOS Apple Silicon 全新安装、升级、LaunchAgent 启动、Gatekeeper 提示路径和无终端弹窗。
- 统一入口页在未安装、正在连接、已连接、正在恢复和需要修复五种状态下均有正确反馈。
- 安装结束后能够自动打开本地 WebUI；以后从统一入口可稳定进入。
- 空闲状态不使用 GPU，CPU 接近 0，并记录实际常驻内存。
- 抖音及其他受支持公开链接的识别失败不会导致本地服务崩溃。
- 横版、竖版和方形视频预览窗口按真实媒体比例适配；旋转、时间码、倍速、分辨率和全屏控件有效。
- 下载中断后任务和临时文件仍可恢复；成功后文件校验、状态和提示音正确。
- 服务异常退出可按退避策略恢复；反复失败时触发熔断并显示可执行的修复说明。
- 更新包签名、哈希、健康检查和自动回退均通过。
- API 只监听回环地址，受保护接口拒绝无效令牌，日志不泄露敏感字段。
- GitHub Actions 只构建 Windows x64 与 macOS Apple Silicon；下载页和更新清单不再产生 Intel 入口。

## 14. 不在本次范围内

- 云端解析、云端下载或付费服务器。
- 浏览器扩展。
- macOS Intel 支持。
- 视频超分。
- 绕过付费、广告解锁、DRM、登录、验证码、地区限制或平台风控。
- 未经系统确认的静默安装。

## 15. 与现有工程的关系

当前仓库已经具备统一下载页、本地 WebUI、8515 回环服务、单实例锁、本地会话令牌、Windows 安装脚本、macOS LaunchAgent、更新签名与自动化测试基础。本设计要求在这些现有模块上增量加固，不替换已经稳定工作的识别、预览和下载功能，也不另建第二套应用。

后续实施计划必须先通过测试锁定现有行为，再逐项增加常驻守护、状态持久化、恢复熔断、入口页状态机、安装完成自动打开、Apple Silicon 单架构发布和验收覆盖。
